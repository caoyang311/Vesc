# FOC正余弦浮点查表方案设计

## 1. 文档目的

本文档用于确定FOC Park变换和反Park变换所需正弦、余弦值的实现方案。

当前工程已经具备FOC算法模块，Park变换接口使用`Foc_TrigType`接收正弦和余弦值。后续通过独立的正余弦查表模块生成`float`格式结果，避免在TIM1快速控制路径中直接调用`sinf()`和`cosf()`。

本文档只定义方案、接口边界和验证要求，不包含具体代码实现。

## 2. 架构定位

根据[MCU软件架构设计文档](./SoftWare_Architecture.md)，FOC属于硬实时快速控制域：

```text
TIM1更新中断
  -> 读取三相电流
  -> Clarke变换
  -> 电角度正余弦计算
  -> Park变换
  -> 电流环控制
  -> 反Park变换
  -> SVPWM
  -> 更新PWM比较值
```

正余弦查表模块应满足：

- 仅提供纯算法服务，不访问HAL、寄存器和物理引脚。
- 不使用动态内存。
- 不调用阻塞函数和标准数学库三角函数。
- 查表和插值执行时间固定且有界。
- 适合TIM1快速控制ISR调用。
- 输入输出采用单精度浮点，和当前FOC算法模块保持一致。
- 查表数据存放在只读存储区，运行时不修改。

## 3. 方案目标

### 3.1 功能目标

输入电角度，输出：

```text
sin(theta)
cos(theta)
```

输出值类型为`float`，理论范围为：

```text
-1.0F <= sin(theta) <= 1.0F
-1.0F <= cos(theta) <= 1.0F
```

### 3.2 实时性目标

查表模块单次调用应为固定上限执行时间，主要操作限定为：

1. 角度归一化或相位索引处理。
2. 象限判断。
3. 查表读取。
4. 一次线性插值。
5. 符号修正。
6. 输出结构体写入。

禁止在快速路径中执行：

- `sinf()`、`cosf()`、`fmodf()`等数学库函数。
- 动态内存分配。
- 不确定长度的循环。
- 角度字符串解析或协议处理。
- 阻塞等待。

## 4. 推荐总体方案

推荐采用：

> **四分之一周期浮点正弦表 + 象限对称映射 + 线性插值 + 统一相位输入**

该方案只存储第一象限`0 ~ PI/2`的正弦值，通过三角函数对称关系同时获得全周期正弦和余弦。

### 4.1 推荐查表规模

第一版推荐配置：

| 项目 | 推荐值 |
|---|---:|
| 查表范围 | `0 ~ PI/2` |
| 查表节点数 | 257点 |
| 查表区间数 | 256段 |
| 节点间隔 | `PI/512` |
| 表元素类型 | `float` |
| 单张表容量 | 257 × 4 = 1028字节 |
| 运行时插值 | 一次线性插值 |
| 存储位置 | Flash只读区 |

257个节点可将第一象限等分为256段，使索引计算简单，并保留`PI/2`端点，避免边界点特殊补偿。

### 4.2 精度与资源权衡

可选配置如下：

| 节点数 | 区间数 | 单表Flash容量 | 适用场景 |
|---:|---:|---:|---|
| 65 | 64 | 260字节 | 资源极限、精度要求较低 |
| 129 | 128 | 516字节 | 常规控制、较低Flash占用 |
| 257 | 256 | 1028字节 | 推荐，精度和实时性平衡 |
| 513 | 512 | 2052字节 | 高精度控制，Flash占用增加 |

最终节点数应结合电流环采样周期、控制器带宽、允许角度误差和Flash预算确认。若无额外测量依据，采用257点作为V1.0默认配置。

## 5. 角度输入设计

### 5.1 推荐使用归一化机械无关相位

不建议在快速路径中以弧度浮点数作为唯一内部表示，因为弧度输入需要处理周期回绕，可能引入浮点取模、边界和累计误差问题。

推荐内部使用`uint16_t`相位表示一个完整电周期：

```text
0x0000 -> 0°
0x4000 -> 90°
0x8000 -> 180°
0xC000 -> 270°
0xFFFF -> 接近360°
```

相位定义：

```text
angle = phase / 65536 × 2PI
```

优点：

- 一个完整电周期自然回绕。
- 不需要运行时浮点取模。
- 索引和象限判断可通过整数位操作完成。
- 适合编码器、电角度累加器和定时控制器。
- 角度输入范围天然固定，边界行为明确。

### 5.2 与现有接口的衔接

当前`Foc_TrigType`仅保存正弦、余弦值：

```c
typedef struct
{
    float sine;
    float cosine;
} Foc_TrigType;
```

建议保持该接口不变，由查表模块负责将相位转换为`Foc_TrigType`，再传给Park或反Park变换：

```text
Foc_PhaseType
  -> Foc_Trig_Lookup
  -> Foc_TrigType
  -> FocAlgorithm_Park / FocAlgorithm_InversePark
```

查表模块不应直接修改Park变换接口，避免算法变换和角度生成职责耦合。

### 5.3 弧度接口的处理建议

如果上层现有传感器或位置模块只能提供弧度浮点数，建议在非硬实时边界完成弧度到`uint16_t`相位的转换，再将相位传入快速查表函数。

不建议在TIM1更新ISR内执行：

- 浮点弧度归一化。
- 浮点除法计算查表索引。
- `fmodf()`周期回绕。
- 依赖`PI`宏的浮点角度转换。

## 6. 查表与插值算法

### 6.1 第一象限查表

第一象限相位范围：

```text
0 <= theta <= PI/2
```

查表节点：

```text
table[0]   = sin(0)
table[256] = sin(PI/2)
```

对于输入相位，提取：

- 象限编号。
- 第一象限等效相位。
- 查表段索引。
- 段内插值比例。

### 6.2 线性插值

设等效相位落在第`k`段，段内比例为`r`，其中：

```text
0 <= r < 1
0 <= k < 256
```

插值公式：

```text
sin_value = table[k] + r × (table[k + 1] - table[k])
```

线性插值相比只取最近节点可显著降低表格量化误差，同时执行时间仍然固定。

### 6.3 余弦计算

不单独建立余弦表，使用相位偏移关系：

```text
cos(theta) = sin(theta + PI/2)
```

实现上可对输入相位增加四分之一周期偏移后再次执行同一查表映射。

推荐两种实现方式：

#### 方式A：同一次象限解析同时生成正余弦

一次完成正弦和余弦的象限映射，分别计算两个等效第一象限索引。

优点：

- 只进行一次公共相位解析。
- 可减少重复逻辑。
- 运行时间更短。

缺点：

- 象限映射代码更复杂。
- 边界条件需要重点验证。

#### 方式B：余弦使用相位加偏移后复用正弦查表函数

```text
sine = LookupSin(phase)
cosine = LookupSin(phase + 0x4000)
```

优点：

- 代码结构简单。
- 正弦查表逻辑单一，容易验证。
- 易于单元测试和复用。

缺点：

- 需要执行两次查表路径。
- WCET略高。

**推荐V1.0采用方式A或经过编译器内联后的等价实现，以降低快速控制路径执行时间；如果优先考虑验证简洁性，则采用方式B。最终选择应以WCET测量结果为依据。**

## 7. 数据存储方案

### 7.1 查表数据

查表数据应定义为：

- 文件内私有对象。
- `const`修饰。
- `float`元素类型。
- 放置在Flash只读区。
- 不允许运行时修改。
- 不使用动态初始化。

建议查表数据独立于公共头文件，避免公共接口暴露完整表内容。

### 7.2 查表生成与版本固化

查表数据不建议手工逐项录入。建议使用离线脚本生成，并将生成参数固化在设计记录中：

- 表范围：`0 ~ PI/2`。
- 节点数：257。
- 数据类型：IEEE 754单精度浮点。
- 常量精度和舍入方式。
- 生成工具版本。
- 生成日期和校验值。

生成后的数组应作为受控源代码的一部分进行评审，不允许运行时生成表格。

## 8. 模块接口规划

建议后续新增独立模块文件：

```text
FOC/
  FocAlgorithm.c
  FocAlgorithm.h
  FocTrigTable.c
  FocTrigTable.h
```

职责划分：

| 文件 | 职责 |
|---|---|
| `FocAlgorithm.c/.h` | Clarke、Park、反Park、SVPWM等变换算法 |
| `FocTrigTable.c/.h` | 正弦查表数据、相位映射和正余弦输出 |

建议公共接口方向：

```c
void FocTrig_GetSinCos(uint16_t phase,
                       Foc_TrigType * trig);
```

接口约束：

- `phase`表示完整电周期的无符号16位相位。
- `trig`为输出结构体指针，不得为NULL。
- 函数无返回值，输入相位始终合法。
- 输出结构体仅在输出指针有效时更新。
- 函数不访问硬件、不分配内存、不阻塞。

函数命名、具体头文件命名和是否保留空指针防御逻辑，应在实现任务开始前最终确认。

## 9. 边界行为

必须明确并固定以下边界：

| 输入 | 期望行为 |
|---|---|
| `0x0000` | `sin=0.0F`，`cos=1.0F` |
| `0x4000` | `sin=1.0F`，`cos=0.0F` |
| `0x8000` | `sin=0.0F`，`cos=-1.0F` |
| `0xC000` | `sin=-1.0F`，`cos=0.0F` |
| `0xFFFF` | 输出接近`sin(-2PI/65536)`和`cos(-2PI/65536)` |
| 相位回绕 | 使用无符号16位自然回绕，不产生异常状态 |
| 输出指针为NULL | 不执行写操作；需按接口策略处理 |

查表索引必须保证：

```text
0 <= index < 256
index + 1 <= 256
```

不得访问表边界之外的数据。

## 10. 精度评估

验证时至少统计：

- 正弦最大绝对误差。
- 余弦最大绝对误差。
- 正余弦单位圆误差：`abs(sin² + cos² - 1)`。
- 0°、30°、45°、60°、90°等关键角度误差。
- 象限边界误差。
- 相位回绕连续性。
- Park和反Park往返误差。

建议验收目标由控制算法需求确定。若暂时没有明确指标，V1.0可先使用以下工程评估门槛：

- 关键角度误差不超过项目规定的单精度计算误差预算。
- 四个象限边界不存在符号错误或跳变。
- `sin² + cos²`误差应纳入电流环误差预算评审。
- 查表模块输出不得出现NaN或无穷值。

上述指标需要通过离线高精度参考值和目标编译器生成结果进行确认，不能仅凭静态检查认定满足。

## 11. 性能与WCET评估

在STM32F303目标编译配置下，需要测量：

- 单次正余弦查表耗时。
- Park变换加查表总耗时。
- 反Park变换加查表总耗时。
- 最坏象限、最大插值路径耗时。
- Flash访问等待状态对执行时间的影响。
- 编译器优化等级对结果和时序的影响。

查表模块的WCET应小于TIM1快速控制周期预算，并与ADC读取、Clarke、PI、电压限幅和SVPWM共同进行快速链路预算。

## 12. C Safety Coding Standard约束

实现阶段必须遵循：

- 使用唯一头文件保护宏。
- 所有公共接口提供Doxygen注释。
- 所有局部变量显式初始化。
- 查表数组使用`static const`，禁止动态内存。
- 索引使用明确的无符号整数类型，并在访问前保证边界。
- 避免隐式窄化和有符号/无符号混合运算。
- 不使用未限定范围的循环。
- 不使用递归、阻塞调用和运行时数学库三角函数。
- 输入输出指针契约必须说明方向、空指针行为和所有权。
- 查表生成工具、数据版本和校验值纳入配置管理。
- 静态分析发现必须分类为已修复、误报或批准偏离。

## 14. 版本建议

### V1.0：基础查表方案

- 四分之一周期257点浮点正弦表。
- `uint16_t`完整电周期相位输入。
- 象限映射。
- 线性插值。
- 同时输出正弦和余弦。
- 不调用数学库三角函数。

### V1.1：精度与性能确认

- 完成离线误差统计。
- 完成目标机WCET测量。
- 根据误差和Flash占用决定是否调整为129点或513点。
- 完成Park、反Park往返验证。

### V2.0：控制系统集成

- 接入转子电角度来源。
- 接入TIM1快速控制链。
- 完成电流环和SVPWM整体时序预算。
- 建立静态分析、单元测试和目标机测试证据链。

## 15. 结论

推荐采用四分之一周期257点`float`正弦查表、象限对称映射和线性插值方案，使用`uint16_t`表示完整电周期相位，并通过相位偏移或统一象限计算同时获得正弦和余弦值。

该方案符合当前FOC硬实时架构，能够避免标准数学库三角函数带来的不可控执行时间，同时在Flash占用、实现复杂度和计算精度之间取得平衡。具体代码实现前，应先完成节点数、相位接口、象限映射方式、精度目标和WCET预算的评审确认。
